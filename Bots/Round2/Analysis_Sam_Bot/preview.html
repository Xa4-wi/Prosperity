Round 2 non-determinism report

Data used: uploaded Round 2 run JSON / log / Python files for 288581, 288483, 276842, 276169, and 274863, plus the earlier 276094 and 219864 results for context where useful.

Executive summary.
1) Testing non-determinism is real and large: exact same code moved by 132.12 and 230.09 XIRECs across reruns, and the same trading logic with only a different bid() moved by 45.20.
2) The stronger direction is the Logic A family (276842 / 288581 / 288483): mean profit 9352.58 versus 9172.77 for Logic B, with lower variability (92.14 vs 162.70).
3) The average gap between Logic A and Logic B is 179.81, driven mostly by Osmium (142.48) rather than Pepper (37.33).
4) The visible order book itself changes a lot between reruns: exact-same-code pairs see different valid mids in roughly half of timestamps, spread differences around 1.4–1.8 ticks on average, and missing bid/ask flips around 7–9% of timestamps. That means robust alpha has to survive quote thinning rather than memorize a single run.

3. Exact same code: how much does one rerun move?

Noise floor.
The observed exact-code ranges were: Logic A exact same code: 132.12, Logic B exact same code: 230.09.
Practical implication: if a new idea only improves one submission by 30–80 XIRECs, that is below or near the realized noise floor. Treat it as unproven until it wins on repeated reruns or improves the 25th percentile.

Why this matters.
These are exact-same-code comparisons, so any difference comes from the simulated market view. The visible best levels change materially between reruns:
  • valid best-mid changed on roughly 47–52% of timestamps in exact-code pairs,
  • average visible spread difference was about 1.4–1.8 ticks,
  • missing bid / ask state flipped on about 7–9% of timestamps.
This is why raw-touch strategies feel magical on one upload and useless on another.
Robust signal hint.
The stable top-3 mid is materially less noisy across reruns than the raw one-sided touch. That supports continuing to build Osmium off anchor + stable/wall mid + bounded fast signal, and to keep vacuum handling / one-sided-book logic explicit rather than trusting the visible touch blindly.

6. What hurts the bot

  • Baking in access-style aggression during no-access randomized tests. Logic B adds larger front/back size, wider join edge, deeper take depth, and explicit access-sweep bonuses. In the observed runs that hurt both average profit and stability versus Logic A.
  • Letting Osmium end too structurally short. Logic B finishes around -31 Osmium on average versus -19.7 for Logic A. That increases dependence on the final mark and makes the strategy more path-sensitive.
  • Trusting raw touch states too much. Missing-side flips and best-level differences are common enough that a bot leaning too hard on best bid/ask or one-tick queue placement becomes unstable.
  • Evaluating ideas on single submissions. The exact same code can move by more than 200 XIRECs. One lucky run is not evidence.

7. What pushes the bot

  • Logic A style Osmium core. This family had the best average result and lower variance. The key theme is moderate local-fair making with markout awareness, rather than assuming access and sweeping deeper levels by default.
  • Pepper carry remains stable. Pepper PnL sits in a relatively narrow band and always ends at +80 position. The upside work should stay focused on Osmium.
  • Stable-book features and vacuum-aware execution. The more the bot anchors to stable/wall mid and explicitly handles one-sided books, the less it depends on the random visible touch.
  • Optimizing the distribution, not the single run. The correct target for Round 2 testing is something like mean - λ·std or the 25th percentile, not max observed PnL.

8. Best interpretation of the uploaded bots

Logic A (276842 / 288581 / 288483).
This is the most promising family in the uploaded set. It is not perfect, but it has the best mean, the best best-case among the compared round-2 runs, and a smaller variance than the access-heavy branch.
Logic B (276169 / 274863).
The idea is plausible for real access, but it is too optimistic for the randomized no-access test harness. The extra JOIN_EDGE, larger front/back sizes, larger TAKE_L3_SIZE, and explicit access sweep bonuses appear to amplify Osmium sensitivity rather than produce a robust gain.

9. Concrete build directions from this report

  1. Keep Logic A as the no-access default base. Do not replace it with Logic B.
  2. Split no-access and access behavior. The access branch should only turn on under a true access-conditioned mode in the backtester, not during default testing.
  3. Add an Osmium terminal recycler. The goal is to shrink the variance of final Osmium inventory under randomized quote thinning, especially on the short side.
  4. Make evaluation multi-run by default. For any new bot, run repeated randomized replays or repeated submissions and store mean, std, and lower-quantile performance.
  5. Use stable/wall mid and bounded fast signal as the core fair. The rerun comparisons support those as more robust than raw touch logic.
  6. Only trust improvements that clear the noise floor. For this environment, I would want roughly +150 XIRECs or more in mean, or a clear lower-tail improvement, before calling a change real.

10. Recommended next experiments

  • A1: Logic A + stronger Osmium recycler. Goal: reduce terminal short variance without reducing throughput.
  • A2: Logic A + stable-mid / vacuum weighting ablation. Goal: verify which pieces are protecting against quote thinning.
  • A3: Logic A + repeated-run score objective. Goal: tune for mean and 25th percentile instead of single-run max.
  • B only in the access backtester. Test Logic B-style access sweeps only under synthetic full-access simulations; do not rely on the public no-access harness to validate them.
